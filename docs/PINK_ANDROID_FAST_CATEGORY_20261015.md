# PINK Android quick category load (candidate, 2026-10-15)

Owner reports that Live TV loads fast while first Movie/Series loads can take several minutes; screenshot shows 120,886 Movies globally, but 657 titles in selected category.

This patch implements an Android **small-phone-only**, on-demand cold-category path where the provider's Xtream `category_id` filter is supported. It queries category metadata first, then retrieves only the selected category through the same **VPN-owned, native, selected-account-bound transport**. The category ID is strictly 1–12 ASCII decimal digits at both JS/native boundary and fixed `player_api.php` builder; untrusted URL/credentials/params are not accepted. For the first cold install without saved preference, a non-adult category is selected visibly, preferring recent/top listings. No auto-choice is made for explicitly selected Favorites/Recents/genres.

The full catalogue remains available by selecting **Todas as categorias**, and global search explicitly triggers the original full-list route. Full and partial IndexedDB cache keys are distinct; a partial response never overwrites the full cache. Return to a previously selected cached category should not re-download its items. Non-Android/TV retain unchanged existing semantics. A provider that ignores `category_id` may still be slow; unsupported scoped calls fall back to full lists.

**Limitations requiring testing:** exact category filter support is unverified against the owner's actual provider, category name collisions trigger safe full fallback, native credential/VPN routing must remain private, physical Android scrolling/frame-time and provider request durations are not verified by emulator-only CI. A UI category mode does not imply every title/genre/favorite is loaded until the user selects All. Do not ship a debug-signed APK over a working phone; issue #54 still applies.

Relates to integrated PR #74 and prior PRs #72/#73. Not a public release.

## 2026-10-15 owner improvement: default All Categories without breaking speed

Owner's QA4 physical screenshots confirm the native category-scoped fast path works (657 films and 1,786 series in the provider's particular MULTI-LANG categories). However, the owner requires both Movies and Series to open in **All Categories**, just like Live TV, and some providers have no MULTI-LANG categories. The earlier heuristic was not hard-coded to MULTI-LANG but favored names like `TOP`, `Recent` and `2026`. That heuristic is removed.

On first native-phone use for each account, the category picker now defaults to **All Categories**, clears any previously automatic category selection once, and thereafter respects manual choices. To retain sub-second usable UI the app first shows a *clearly labelled partial preview* of an available, safe provider category with a `+` on the count; this does **not** pretend to represent the full inventory. It immediately starts the original VPN-protected full `get_vod_streams` / `get_series` fetch in the background and, after complete verification/cache hydration, replaces the preview with the real full catalog and accurate total. Full-catalog cache keys and global search/favorites remain unchanged, as do Android TV and desktop behavior. The cold full request can still take minutes, but the first poster grid stays interactive. If the provider does not support the quick category request, the original full-catalog behavior remains as fallback. Switching account/category during the background fetch cannot paint old-account results into the new view.

The real compiled-page Chromium smoke now verifies default All for both screens and complete fixture results spanning two categories, with no provider credentials. These tests, native emulator/VPN security, lint and signing must pass at the exact integration head before any APK handoff. Existing QA4 debug signature must **not** be replaced by a new ephemeral signer; use a separate safely verified QA identity for any owner test build.
